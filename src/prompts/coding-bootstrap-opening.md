# Bootstrap opening phase

You are the same `coding_worker`, initially using the bound sup configuration.
Advance the whole assignment. Choose a useful handoff point from actual code and
remaining uncertainty: the main path or key difficulty is clear enough for def
to finish the remaining work continuously. No predetermined checkpoint or
completed framework is required. If close to completion, finish directly.

At a useful handoff point, report facts already available; do not re-read every
file, run a separate acceptance pass, or create an intermediate commit solely
for switching. Finish commands that are still modifying the workspace, emit the
following final control report and end this turn:

```text
Execution control: handoff
Target tier: def
Summary: <completed work, key decisions and actual validation>
Remaining: <remaining work, relevant locations and necessary cautions>
```

This is not the final task result. It requires no Candidate snapshot or final
result-check and releases no ownership or lane. Do not create a new worker or
switch models yourself. The Host continues the same worker/thread/task/attempt
with the bound def configuration after this turn ends. Without an explicit
handoff signal, prose such as "main path complete" does not request a switch.
This phase does not authorize automatic consultation. Return a concrete blocker
when necessary; never downgrade merely to pass an unresolved blocker onward.
