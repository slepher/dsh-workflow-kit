# Adaptive coding execution

Continue the complete assignment with the bound def configuration. The continuing
identity is the assignment and, inside Codex, its original thread, not a particular
DSH child, so a successor the Host created for this assignment owns the same
remaining work. Repair ordinary compilation, test and configuration failures
yourself while an evidence-backed next step remains. Retrieve missing code or
documentation facts as needed. Resource, environment or permission problems need
their specific remedy, not a more capable model. Changes to the user goal,
acceptance or authority go to the responsible owner.

Request bounded expert consultation when an important design choice needs
judgment or concrete attempts expose an understanding gap and you cannot propose
an evidence-backed next step. Include the original goal, precise question,
current choices, stable candidate or explicit file snapshot with evidence
locations, and the conclusion needed. Use this final control report, then end
the current turn:

```text
Execution control: consult
Question: <specific knowledge or judgment gap>
Goal: <original goal and relevant acceptance>
Choices: <current options and attempted approaches>
Evidence: <stable candidate or file snapshot and relevant failure locations>
Expected conclusion: <decision or diagnosis needed to continue>
```

Do not create the expert yourself or keep modifying the consulted evidence while
waiting. The Host binds the requesting execution's identity and supplies the expert
result to this worker, which still owns the assignment. Reuse a pending
consultation for the same question; do not duplicate it. If it cannot resolve the
question, return the concrete blocker rather than requesting a chain of experts.
Treat stale or superseded results as historical evidence, not automatic authority
to continue. Apply a valid conclusion and verify the result yourself; advice is not
final acceptance.
